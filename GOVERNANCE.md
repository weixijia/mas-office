# Governance

MAS Office is a young project with a simple, written-down process, so that it can grow without surprises.

## Roles

- **Contributors**: anyone who opens an issue, reviews, or sends a pull request.
- **Maintainers**: can merge pull requests and cut releases. They review in a reasonable time, keep the spec and both SDKs consistent, and follow the Code of Conduct's enforcement guidelines.
- **Lead maintainer**: breaks ties and owns the release keys.

| Maintainer | Areas |
|---|---|
| [@weixijia](https://github.com/weixijia) (lead) | everything |

## Becoming a maintainer

After several merged, substantial contributions and helpful reviews, any maintainer can propose you in an issue. You become a maintainer when no maintainer objects within 7 days. We especially want maintainers for individual integrations and for the Python SDK.

## Decisions

- Day-to-day changes: one maintainer approval.
- Spec RFCs: two maintainer approvals and at least 7 days open (while there is only one maintainer, the RFC stays open 14 days for community feedback instead).
- Disagreements: discuss on the issue; if there is no consensus, the lead maintainer decides and writes down why.

## Changes to this document

By pull request, with the same rule as a spec RFC.
